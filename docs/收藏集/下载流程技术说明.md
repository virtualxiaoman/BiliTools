# Bilibili 装扮 / 收藏集下载流程技术说明

> 本文只描述项目的**数据获取、资源解析与文件下载流程**，不讲解界面、控件和页面交互。
>
> 目标读者：希望理解“一个搜索结果如何最终变成若干本地图片/视频文件”的程序员。
>
> 相关实现：
>
> - `gui_app/config/api.py`：接口地址和公共请求头
> - `gui_app/core/api_client.py`：JSON API 请求封装
> - `gui_app/core/downloader.py`：详情解析、资源枚举、文件下载
> - `gui_app/ui/threads.py`：将搜索/下载放到后台线程中执行

---

## 1. 总览：这是一个“两阶段元数据查询 + 多次媒体文件下载”的程序

程序不会在搜索阶段直接下载素材。完整链路分为三类 HTTP 请求：

1. **搜索请求**：根据关键词获取候选条目，并确定条目是“装扮”还是“收藏集”。
2. **详情请求**：根据候选条目中的标识符获取真正的资源描述，包括图片、视频的 URL。
3. **媒体下载请求**：对详情响应中返回的每一个资源 URL 发起普通 HTTP `GET`，将响应二进制流写入本地文件。

可以将链路概括为：

```text
关键词
  │
  ▼
搜索 API
  │ 返回候选项：name / part_id / item_id / properties
  ▼
根据 part_id 判断条目类型
  ├─ 收藏集：从 properties 取 act_id + lottery_id
  │     │
  │     ▼
  │   收藏集详情 API
  │     │ 返回 cover、item_list[].card_info.card_img、video_list
  │     ▼
  │   逐个下载封面、卡图和视频
  │
  └─ 装扮：取 item_id
        │
        ▼
      装扮详情 API
        │ 返回 suit_items（表情、空间海报、主题等资源集合）
        ▼
      按用户指定的资源类别提取 URL，并逐个下载
```

这里的核心原则是：

- 搜索接口返回的是**定位详情所需的标识符**；
- 详情接口返回的是**可下载资源的 URL**；
- 文件下载器不理解 Bilibili 的业务含义，只负责把 URL 对应的二进制内容保存到目标路径。

## 2. 公共网络配置

全部请求都会带上 `gui_app/config/api.py` 中的公共请求头：

```python
HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
    "Referer": "https://www.bilibili.com/",
}
```

程序不携带 Cookie、`SESSDATA`、OAuth Token 或 CSRF 参数。因此它依赖的是接口和资源 URL 对未登录访客仍然可访问这一前提。

当前项目使用的 JSON API 有三个：

| 目的 | HTTP 方法 | URL | 请求参数 |
|---|---|---|---|
| 搜索装扮/收藏集 | `GET` | `https://api.bilibili.com/x/garb/v2/mall/home/search` | `key_word`、`ps`、`pn` |
| 获取装扮详情 | `GET` | `https://api.bilibili.com/x/garb/v2/mall/suit/detail` | `item_id` |
| 获取收藏集详情 | `GET` | `https://api.bilibili.com/x/vas/dlc_act/lottery_home_detail` | `act_id`、`lottery_id` |

媒体文件没有固定 API 地址。它们的 URL 来自详情 JSON，常见域名包括图片 CDN `i0.hdslb.com` 和视频 CDN `upos-*.bilivideo.com`。

## 3. 阶段一：搜索并获得下载任务的“入口标识”

### 3.1 请求

搜索由 `ApiClient.search_items()` 执行：

```python
params = {
    "key_word": keyword,
    "ps": 20,
    "pn": 1,
}

requests.get(SEARCH_API, params=params, headers=HEADERS, timeout=30)
```

若关键词为 `初音未来`，HTTP 请求等价于：

```text
GET https://api.bilibili.com/x/garb/v2/mall/home/search
    ?key_word=初音未来
    &ps=20
    &pn=1
```

参数含义：

| 参数 | 含义 | 当前代码中的取值 |
|---|---|---|
| `key_word` | 搜索关键词 | 调用方输入的字符串 |
| `ps` | 单页最大结果数 | 固定为 `20` |
| `pn` | 页码 | 固定为 `1` |

因此，当前实现**只取第一页、最多 20 条结果**，不会自动翻页。

### 3.2 成功判断与返回值

HTTP 层面先执行 `resp.raise_for_status()`；若状态码为 4xx/5xx，会立即抛出异常。随后将响应解析为 JSON：

```python
data = resp.json()
if data.get("code") == 0 and data.get("data", {}).get("list"):
    return data["data"]["list"]
return []
```

也就是说，业务成功条件是：

```json
{
  "code": 0,
  "data": {
    "list": [ ... ]
  }
}
```

程序将 `data.list` 中的对象**原样保留为 Python `dict`**，后续不会转换成专门的领域模型。这是理解代码时最重要的事实：后续所有流程都围绕这份原始字典取字段。

### 3.3 后续下载实际需要的字段

一个搜索结果可能包含很多展示、价格、活动字段，但下载流程主要使用以下字段：

```json
{
  "name": "条目名称",
  "part_id": 0,
  "item_id": 111106,
  "properties": {
    "image_cover": "https://...",
    "dlc_act_id": "111106",
    "dlc_lottery_id": "111107"
  }
}
```

| 字段路径 | 含义 | 后续用途 |
|---|---|---|
| `name` | 装扮或收藏集名称 | 创建本地目录、日志显示 |
| `part_id` | 条目类型标记 | `0` 表示收藏集；非 `0` 表示装扮 |
| `item_id` | 装扮 ID | 装扮详情接口的 `item_id` 参数 |
| `properties.dlc_act_id` | 收藏集活动 ID | 收藏集详情接口的 `act_id` 参数 |
| `properties.dlc_lottery_id` | 收藏集抽奖 ID | 收藏集详情接口的 `lottery_id` 参数 |
| `properties.image_cover` | 搜索结果封面 | 当前下载逻辑不使用它下载最终封面，仅可用于展示信息 |

> 注意：不要用搜索结果顶层的 `item_id` 来下载收藏集。当前代码明确以 `part_id == 0` 识别收藏集，并从 `properties.dlc_act_id` 与 `properties.dlc_lottery_id` 获得收藏集详情所需的参数。

## 4. 阶段二：按条目类型请求详情

下载线程 `DownloadThread.run()` 接收三项输入：

```python
item           # 搜索阶段返回的原始 dict
save_dir       # 用户选择的基础保存目录
resource_types # 要下载的资源类别，例如 ["emoji_package", "space_bg"]
```

它的主分支如下：

```python
part_id = item.get("part_id", 0)
properties = item.get("properties", {})

if part_id == 0:
    # 收藏集：使用 dlc_act_id + dlc_lottery_id
else:
    # 装扮：使用 item_id
```

因此，`part_id` 是整个下载流程中最重要的分流字段。

## 5. 收藏集下载流程

收藏集逻辑位于 `Downloader.download_collectible()`。

### 5.1 从搜索项取参数

当 `part_id == 0` 时，代码读取：

```python
act_id = item["properties"].get("dlc_act_id")
lottery_id = item["properties"].get("dlc_lottery_id")
```

如果任意一个值不存在，则直接终止任务并报错：

```text
无法获取收藏集的 act_id 或 lottery_id
```

### 5.2 请求收藏集详情

调用 `ApiClient.get_dlc_detail(act_id, lottery_id)`：

```python
params = {
    "act_id": act_id,
    "lottery_id": lottery_id,
}

requests.get(
    "https://api.bilibili.com/x/vas/dlc_act/lottery_home_detail",
    params=params,
    headers=HEADERS,
    timeout=30,
)
```

例如：

```text
GET https://api.bilibili.com/x/vas/dlc_act/lottery_home_detail
    ?act_id=111106
    &lottery_id=111107
```

响应的业务成功条件是：

```json
{
  "code": 0,
  "data": { ... }
}
```

函数返回 `data.data`，在下载器中命名为 `detail`。

### 5.3 详情数据如何被解释

下载器只读取以下结构：

```json
{
  "cover": "https://cdn.example/cover.jpg",
  "item_list": [
    {
      "card_info": {
        "card_name": "夜行奇术师",
        "card_img": "https://cdn.example/card.png",
        "video_list": [
          "https://cdn.example/card.mp4?..."
        ]
      }
    }
  ]
}
```

| 字段路径 | 类型 | 作用 |
|---|---|---|
| `detail.cover` | `str` | 收藏集封面 URL |
| `detail.item_list` | `list` | 收藏集中的卡片列表 |
| `item.card_info` | `dict` | 单个卡片的资源描述 |
| `card_info.card_name` | `str` | 本地文件名主体 |
| `card_info.card_img` | `str` | 卡图下载 URL |
| `card_info.video_list` | `list[str]` 或空值 | 卡片视频 URL 列表 |

### 5.4 根据资源类别生成下载动作

收藏集支持的资源类别为：

```python
{
    "card_img": "卡片图片",
    "video_list": "卡片视频",
    "cover": "封面",
}
```

处理规则如下：

| 用户选择 | 从详情读取 | 生成的下载动作 |
|---|---|---|
| `cover` | `detail.cover` | 下载为 `cover.<原始扩展名>` |
| `card_img` | `card_info.card_img` | 下载为 `<card_name>.<原始扩展名>` |
| `video_list` | `card_info.video_list[0]` | 下载为 `<card_name>.<原始扩展名>` |

`video_list` 的一个细节：代码只取第一个地址：

```python
video_url = video_list[0]
```

如果接口给出多个视频地址（可能代表不同线路、清晰度或相同资源的多个 CDN），当前实现**只下载第 0 个**。

### 5.5 保存路径

以基础路径 `<base_dir>`、收藏集名称 `<name>` 为例：

```text
<base_dir>\收藏集\<sanitize(name)>\
    cover.jpg
    夜行奇术师.png
    夜行奇术师.mp4
    ...
```

其中 `sanitize(name)` 会替换 Windows 非法文件名字符：

```text
< > : " / \ | ？ *  →  _
```

同时会去掉首尾空格/句点，并将文件名截断到 200 个字符以内。

## 6. 装扮下载流程

装扮逻辑位于 `Downloader.download_suit()`。

### 6.1 从搜索项取参数

当 `part_id != 0` 时，代码读取：

```python
item_id = item.get("item_id")
```

缺失则报错：

```text
无法获取装扮的 item_id
```

### 6.2 请求装扮详情

调用 `ApiClient.get_suit_detail(item_id)`：

```python
params = {"item_id": item_id}

requests.get(
    "https://api.bilibili.com/x/garb/v2/mall/suit/detail",
    params=params,
    headers=HEADERS,
    timeout=30,
)
```

例如：

```text
GET https://api.bilibili.com/x/garb/v2/mall/suit/detail
    ?item_id=418043001
```

若 JSON 顶层 `code == 0`，下载器获得：

```python
detail = response_json["data"]
suit_items = detail.get("suit_items", {})
```

如果 `suit_items` 缺失或为空，任务结束并记录：

```text
该装扮没有可下载的素材
```

### 6.3 `suit_items`：资源 URL 的主要来源

`suit_items` 是一个按资源类别分组的对象。项目支持：

```python
{
    "card": "动态卡片",
    "emoji_package": "表情包",
    "card_bg": "评论装扮",
    "thumbup": "点赞特效",
    "loading": "加载动画",
    "play_icon": "进度条",
    "skin": "个性主题",
    "space_bg": "空间海报",
}
```

下载器不会下载所有类别；仅处理 `resource_types` 中明确包含的类别。例如：

```python
resource_types = ["emoji_package", "space_bg"]
```

意味着只遍历：

```python
suit_items["emoji_package"]
suit_items["space_bg"]
```

其余类别即使在详情响应中存在，也不会下载。

### 6.4 各资源类别的 URL 提取规则

#### A. 动态卡片：`card`

单个条目通常具有：

```json
{
  "name": "卡片名称",
  "properties": {
    "image": "https://...png",
    "fans_image": "https://...png"
  }
}
```

下载规则：

| URL 字段 | 文件名 |
|---|---|
| `properties.image` | `<名称>.<ext>` |
| `properties.fans_image` | `<名称>_fans.<ext>` |

保存目录：`装扮/<装扮名>/动态卡片/`。

#### B. 表情包：`emoji_package`

结构包含嵌套 `items`：

```json
{
  "items": [
    {
      "name": "[系列名_表情名]",
      "properties": {
        "image": "https://...png"
      }
    }
  ]
}
```

下载器读取 `item.properties.image`。若名称符合正则：

```text
[任意内容_表情名]
```

则仅取下划线后的“表情名”作为文件名；否则使用原名称。保存目录：`装扮/<装扮名>/表情包/`。

#### C. 评论装扮：`card_bg`

```json
{
  "name": "背景名称",
  "properties": {
    "image": "https://...png"
  }
}
```

下载 `properties.image`，保存目录：`装扮/<装扮名>/评论装扮/`。

#### D. 点赞特效：`thumbup`

结构和 `card_bg` 类似：

```json
{
  "name": "特效名称",
  "properties": {
    "image": "https://...png"
  }
}
```

下载 `properties.image`，保存目录：`装扮/<装扮名>/点赞特效/`。

#### E. 加载动画：`loading`

```json
{
  "name": "加载动画名称",
  "properties": {
    "loading_url": "https://...webp",
    "loading_frame_url": "https://...png"
  }
}
```

下载规则：

| URL 字段 | 文件名 |
|---|---|
| `loading_url` | `<名称>.<ext>` |
| `loading_frame_url` | `<名称>_frame.<ext>` |

保存目录：`装扮/<装扮名>/加载动画/`。

#### F. 进度条：`play_icon`

此类别没有写死 URL 字段名。代码遍历全部 `properties`：

```python
for key, value in props.items():
    if isinstance(value, str) and value.startswith("http"):
        download(value)
```

即：只要一个 `properties` 值是以 `http` 开头的字符串，就被视为资源 URL。

文件命名为：

```text
<名称>_<properties 中的字段名>.<ext>
```

保存目录：`装扮/<装扮名>/进度条/`。

#### G. 个性主题：`skin`

处理策略与 `play_icon` 完全相同：遍历 `properties` 中所有 HTTP URL 值，保存为：

```text
<名称>_<字段名>.<ext>
```

保存目录：`装扮/<装扮名>/个性主题/`。

#### H. 空间海报：`space_bg`

空间海报使用一组带编号和方向的字段，例如：

```json
{
  "properties": {
    "image1_landscape": "https://...jpg",
    "image1_portrait": "https://...jpg",
    "image2_landscape": "https://...jpg",
    "image2_portrait": "https://...jpg"
  }
}
```

下载器使用正则：

```python
r"image(\d+)_(landscape|portrait)"
```

解析字段名中的：

- 图片序号，例如 `1`、`2`；
- 方向，`landscape`（横图）或 `portrait`（竖图）。

然后生成文件：

```text
<装扮名称>_1_landscape.jpg
<装扮名称>_1_portrait.jpg
<装扮名称>_2_landscape.jpg
<装扮名称>_2_portrait.jpg
```

保存目录：`装扮/<装扮名>/空间海报/`。

### 6.5 装扮文件的目录结构

以 `<base_dir>` 为基础路径：

```text
<base_dir>\装扮\<sanitize(装扮名称)>\
    动态卡片\
    表情包\
    评论装扮\
    点赞特效\
    加载动画\
    进度条\
    个性主题\
    空间海报\
```

只有用户选择且详情中确实存在资源的类别目录才会创建。

## 7. 阶段三：实际的媒体文件下载机制

所有图片、视频下载最终都会进入同一个方法：

```python
Downloader.download_file(url, save_path)
```

其核心实现是：

```python
resp = requests.get(
    url,
    headers=HEADERS,
    timeout=60,
    stream=True,
)
resp.raise_for_status()

with open(save_path, "wb") as f:
    for chunk in resp.iter_content(chunk_size=8192):
        f.write(chunk)
```

这表示：

1. 对详情 JSON 返回的**完整 URL 原样发起 GET 请求**；
2. `stream=True` 表示不一次性把整个文件读进内存；
3. 每次从响应读取 8192 字节（8 KiB）并立即写入磁盘；
4. 请求失败、超时或 HTTP 状态异常时抛出异常；
5. 如果目标文件已创建但下载过程失败，尝试删除该不完整文件。

### 7.1 扩展名如何确定

程序通过 URL 路径推断扩展名：

```python
ext = os.path.splitext(url.split("?")[0])[1]
```

也就是说，会先去掉 URL 中 `?` 之后的查询参数，再使用最后一个扩展名。例如：

```text
https://example.com/asset.webp?token=abc
```

推断为：

```text
.webp
```

如果推断不到扩展名，各类别会使用自己的默认值，例如 `.png`、`.jpg`、`.mp4` 或 `.webp`。

### 7.2 签名视频 URL 的处理

收藏集视频 URL 通常包含类似 `deadline`、`upsig`、`uparams` 等查询参数。这些参数由详情接口返回，可能与访问期限、CDN 鉴权或播放资源有关。

本项目不解析、不刷新、不重签这些参数，而是直接使用该 URL 下载。因此：

- 必须尽快下载详情接口刚返回的 URL；
- 若 URL 已过期，媒体请求可能失败；
- 程序当前没有自动重新请求详情、刷新视频 URL 后重试的机制。

## 8. 执行模型：为什么详情与下载在后台线程中运行

为避免耗时网络请求阻塞主程序，项目定义了两个 `QThread`：

| 线程 | 类 | 负责内容 |
|---|---|---|
| 搜索线程 | `SearchThread` | 调用搜索 API，返回结果列表 |
| 下载线程 | `DownloadThread` | 判断条目类型、获取详情、遍历资源并下载文件 |

对一次下载任务而言，调用链是：

```text
DownloadThread.run()
  ├─ 读取 item.part_id
  ├─ 收藏集：Downloader.download_collectible(...)
  │    ├─ ApiClient.get_dlc_detail(...)
  │    └─ 对资源 URL 调用 download_file(...)
  │
  └─ 装扮：Downloader.download_suit(...)
       ├─ ApiClient.get_suit_detail(...)
       └─ 对资源 URL 调用 download_file(...)
```

当前队列的“全部下载”是串行的：一个 `DownloadThread` 完成（成功或失败）后，才启动下一个任务。单个任务内的文件下载也是串行的，没有并发下载多个图片/视频。

## 9. 暂停与终止在下载循环中的实际行为

`Downloader` 保存两个执行控制状态：

```python
self._is_running = True
self._is_paused = False
```

### 暂停

暂停并不会取消已经建立的 HTTP 连接；它在每一个 8 KiB 数据块写入前检查状态：

```python
while self._is_paused and self._is_running:
    time.sleep(0.1)
```

因此暂停的效果是：当前文件下载在下一个块处理点停止向磁盘写入并等待恢复。

### 终止

终止会把：

```python
self._is_running = False
```

下载循环在下次检查时返回。对当前已打开但未完成的文件，异常处理/控制流会尝试避免留下完整性未知的文件，但该实现并不提供断点续传。

## 10. 错误处理与当前实现的边界

### 10.1 HTTP 与业务错误

JSON API 请求分两层检查：

1. `raise_for_status()`：处理 HTTP 4xx/5xx；
2. `data["code"] == 0`：处理 Bilibili 的业务状态。

但有一个实现细节：当 HTTP 成功、JSON 也合法，但 `code != 0` 时，当前代码通常返回 `None` 或空列表，**没有把 API 的 `message` 字段带入错误信息**。这会降低排障效率。

### 10.2 不存在自动重试

GUI 版的 `download_file()` 没有重试循环。任意单个媒体 URL 下载失败会抛出异常，进而使当前整个下载任务失败。

### 10.3 不存在断点续传或校验

当前实现没有：

- `Range` 请求；
- 临时 `.part` 文件；
- 文件哈希校验；
- 已存在文件跳过策略；
- 下载完成后的内容类型校验。

因此重复运行会覆盖同名文件；下载中断后需要重新下载该文件。

### 10.4 进度是“条目估算”，不是字节进度

代码虽读取过 HTTP `Content-Length`：

```python
total_size = int(resp.headers.get("content-length", 0))
```

但该值未参与进度计算。界面中的百分比由“处理过多少业务资源条目”估算得出，而不是已经接收的字节比例。

部分资源条目可能包含多个文件，例如：

- 一项动态卡片同时有 `image` 和 `fans_image`；
- 一项加载动画同时有 `loading_url` 和 `loading_frame_url`；
- `play_icon` 与 `skin` 会包含数量不固定的 URL 字段。

因此显示进度不一定与真实文件数或真实网络字节数严格一致。

## 11. 一次请求到落盘的完整示例

假设搜索关键词为 `初音未来`，搜索接口返回一个收藏集条目：

```json
{
  "name": "初音未来live集-未来有你魔法星夜",
  "part_id": 0,
  "properties": {
    "dlc_act_id": "111106",
    "dlc_lottery_id": "111107"
  }
}
```

若选择资源：

```python
["cover", "card_img", "video_list"]
```

则实际流程为：

```text
1. GET /x/garb/v2/mall/home/search
   参数：key_word=初音未来, ps=20, pn=1
   得到：part_id=0、dlc_act_id=111106、dlc_lottery_id=111107

2. 判定为收藏集，因为 part_id == 0。

3. GET /x/vas/dlc_act/lottery_home_detail
   参数：act_id=111106, lottery_id=111107
   得到：
       data.cover
       data.item_list[].card_info.card_name
       data.item_list[].card_info.card_img
       data.item_list[].card_info.video_list[0]

4. 对 data.cover 发 GET，写入：
   <base_dir>/收藏集/初音未来live集-未来有你魔法星夜/cover.jpg

5. 对每张 card_img 发 GET，写入：
   <base_dir>/收藏集/初音未来live集-未来有你魔法星夜/<卡片名>.png

6. 对每个 card_info.video_list[0] 发 GET，写入：
   <base_dir>/收藏集/初音未来live集-未来有你魔法星夜/<卡片名>.mp4
```

装扮条目的流程完全对应，只是第 3 步改为：

```text
GET /x/garb/v2/mall/suit/detail?item_id=<item_id>
```

并从 `data.suit_items` 中按资源类别解析不同字段。

## 12. 阅读和重构此项目时应抓住的核心数据契约

如果要继续维护或重构，建议始终围绕以下三层数据契约思考：

```text
SearchResult
    负责：确定条目类型、提供详情查询 ID

DetailResponse
    负责：提供该条目所有可下载资源的元数据和 URL

DownloadJob
    负责：一个确定的 source_url + target_path
```

当前代码中，前两层以原始 `dict` 存在，第三层没有显式建模，而是“解析到 URL 后立刻下载”。更容易维护的设计应先将详情转换为明确的下载任务列表：

```python
@dataclass
class DownloadJob:
    source_url: str
    target_path: Path
    category: str
```

理想执行流程：

```text
搜索结果 dict
  → 规范化 SearchItem
  → 请求详情
  → 解析为 list[DownloadJob]
  → 统计任务总数
  → 逐个执行 DownloadJob
  → 记录成功、失败、进度
```

这样做可以消除大量 `dict.get(...)`、`part_id == 0` 和资源类型分支散落在不同位置的问题，也能让进度、重试、跳过已存在文件、断点续传等能力更容易加入。
