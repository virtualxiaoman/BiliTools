## 1. 背景与目标

### 1.1 背景

BiliTools 已支持视频/收藏夹/合集/UP主/装扮下载，以及视频评论、动态评论获取（`ReplyService.get_dynamic_comments`）。动态（opus）本身尚不能下载。

动态与视频不同：一个动态是"多条内容 + 多种媒体 + 社交元数据"的复合体，可能包含纯文字、表情包、图片（含长图/动态图）、视频卡、专栏长文、商品卡、直播预约、互动抽奖、投票、转发链等。因此不能沿用"单文件"下载模型，需要新的目录化输出格式。

### 1.2 目标（一期）

- 单条动态（ID 或 opus 链接）完整落盘：正文、图片、表情、卡片元数据、评论（默认前 20 条热评）。
- 转发动态递归下载，原动态写入原作者目录。
- 可复用资源（头像/挂件/表情）按 UP 目录缓存，不重复下载。
- 缓存命中自动跳过；`force=True` 全部重下。
- 提供 `examples/dynamic.py` 示例与 `docs/功能介绍.md` 更新。

### 1.3 范围外（二期）

- 按 UP 空间列表批量下载（`feed/space` 翻页 + 多线程 + 多账号分流 + `RiskGate`）。
- PySide6 GUI"动态"页签（`DownloadSource` / `MediaType` 扩展、worker 分流、进度面板接入）。
- 关注流/首页动态（`feed/all`，需登录，暂不做）。

## 2. 已确认的格式规范（评审基线，实现不得偏离）

### 2.1 目录结构

```
output/dynamic/{mid}/                       # 顶层按 UP 的 mid 聚合
├── _assets/                                # 该 UP 的资源层（缓存 + 媒体）
│   ├── profile.json                        # 昵称/头像/装扮快照（每次下载顺带刷新）
│   ├── manifest.json                       # 可复用资源（头像/挂件/表情）URL → 文件 映射
│   ├── avatar_{昵称}.{ext}
│   ├── pendant_{挂件名}.{ext}               # 挂件（无则跳过）
│   ├── decorate_{装扮名}.{ext}              # 装扮卡（无则跳过）
│   ├── emojis/{package_id}/{表情短名}.{ext} # gif 优先，webp 兜底
│   ├── images/                             # 正文图片：{动态发布日期}_{当日自增号}.{ext}
│   │   ├── index.json                      # 账本：(动态ID/图片序号) → 文件名，重试/force 不换号
│   │   └── 2026-09-21_1.png 2026-09-21_2.jpg …（每天从 _1 重新计数）
│   └── covers/                             # 卡片封面：同命名规则，独立计数器
│       ├── index.json
│       └── 2026-09-21_1.jpg …
└── {YYYY-MM}/                              # 按月分组（北京时间）
    └── {YYYY-MM-DD}_{当天序号}/             # 见 2.2
        ├── dynamic_id.txt                  # 纯动态 ID；最后写入 = 完成标记
        ├── dynamic_id_failed.txt           # 媒体最终失败时写（内容同样是动态 ID），与成功标记互斥，便于统计成败
        ├── dynamic.md                      # 主产物（人类可读）
        ├── dynamic.json                    # 结构化解析结果（脚本消费）
        ├── raw.json                        # 原始 API 响应（追溯用）
        └── comments.json                   # 评论存档（默认前 20 条热评）
```

- 目录名全部经 `src/util/filename.py::sanitize_filename` 清洗；日期按 `pub_ts` 换算北京时间。
- 图片 URL 统一 `http://` → `https://`；扩展名从 URL 后缀推断，无法识别时按响应头兜底、默认 `.jpg`。
- 动态 ID 随发布时间递增，动态目录的当天序号即发布顺序（见 2.2）；媒体文件编号规则见 2.6。
- live photo（`live_url` 非空）与普通图片共用编号规则、扩展名 `.mp4`，`dynamic.json` 中标记 `live: true`（文件名不加额外后缀，保持编号规则纯净）。

### 2.2 序号算法（追加编号）

- **批量（二期）**：同一天的条目按 `pub_ts` 升序排序后顺序编号（列表在手，零额外请求，结果=发布序）。
- **单条**：取该日期下已有目录的最大序号 + 1；下载前先扫描当天目录中 `dynamic_id.txt`，命中目标 ID 则直接复用路径（幂等）。
- 历史目录**永不改名**；并发落地时先预分配序号，目录创建用独占语义，撞名顺延。

### 2.3 缓存判定（输入 ID/URL）

1. 请求 detail 拿 `mid` / `pub_ts`（这步无法省，且可顺带刷新 `_assets/profile.json`）；
2. 计算 `output/dynamic/{mid}/{YYYY-MM}/`，扫 `{YYYY-MM-DD}_*/dynamic_id.txt`：
   - 命中目标 ID → **动态级缓存命中**，直接返回 `cached=True`；
3. 未命中 → 分配序号、下载；
4. `dynamic_id.txt` 在全部资源完成后**最后写入**（临时文件 + `os.replace` 原子替换）；媒体失败自动重试一次，仍失败则改写 `dynamic_id_failed.txt`（与成功标记互斥），半成品目录不会被误判；
5. 动态级 miss 时，媒体文件先查 `_assets/*/index.json` 账本：有记录且文件非空 → 跳过；有记录但文件缺失 → 复用原号重下；无记录 → 分配新号（见 2.6）。中断重试成本低。

### 2.4 force 语义

- `force=True`：动态内容 + `_assets` 全部重下（忽略 manifest 缓存与账本状态，重下头像/表情、图片、封面）。
- 媒体文件**复用账本中已分配的文件名覆盖写**（不重新分配编号，避免重复文件）；不主动删除旧文件。
- 完成后依旧最后重写 `dynamic_id.txt`。

### 2.5 其他已定决策

| 项 | 决策 |
|---|---|
| 转发递归 | 原动态完整下载，写入**原作者自己的 UP 目录**；`max_forward_depth=3` 防循环；原动态已删除时 md 渲染占位 |
| 卡片策略 | 视频/直播/专栏/番剧/课程等只存元数据 + 封面到 `_assets/covers/`，本体不下载（视频可用 VideoService 另行下载） |
| 互动抽奖 | 存抽奖节点 rid + 原动态链接（实测节点 `jump_url` 为空）；`additional.upower_lottery` 有数据时一并存 JSON+渲染 |
| 投票 | 存选项文本与 rid（暂无实测样本，按 raw + 文本降级） |
| 评论 | 默认 `with_comments=True, max_count=20, sort="hot"`；可关闭、可改 -1 全量 |
| 序号含义 | 混用（批量=发布序、单条=追加序）为用户已接受的代价 |

### 2.6 媒体编号与账本（按日期重置）

- **口径**：每个 UP 的 `_assets/images/`、`_assets/covers/` 各自按**日期独立计数**——每天第一张为 `日期_1`，同日递增，跨日重置（`2026-09-21_3.png` = 2026-09-21 发布的动态对应的第 3 张图）；日期前缀取**动态发布日期**（北京时间），不是下载日期；文件名不含宽高等附加数据（尺寸等保留在 `dynamic.json`）。
- **分配方式**：预分配 + 单点串行。任务构建阶段（下载开始前、单线程）由 `AssetIdAllocator` 在锁内一次性分配全部文件名——`编号 = 当日目录内最大号 + 1`（或账本缓存值）；多线程/多 worker 必须经 `get_asset_allocator` 共享同一实例（同一把锁与账本状态）。分配时用 O_EXCL 原子占位（`touch(exist_ok=False)`）兜底跨进程/崩溃残留冲突，被占用则顺延。下载线程只消费已绑定唯一路径的任务，运行期不查询编号。
- **账本**：`_assets/images/index.json`（covers 同理）记录 `{"<动态ID>/<媒体序号>": {"file": "2026-09-21_253.png", "url": "...", "status": "pending|done"}}`；分配即写入 pending（原子重写），下载成功更新 done。
- **重试/force 不换号**：先查账本复用原文件名（文件缺失则原号重下），无记录才分配新号；编号只增不回退（删除文件不回收编号），账本丢失时用目录扫描自愈。
- images 与 covers 使用各自的计数器，互不影响。

## 4. 技术设计

### 4.1 接口层：`src/urls/dynamic_urls.py`

| 端点 | 用途 | 关键点（实测） |
|---|---|---|
| `x/polymer/web-dynamic/v1/detail` | 单条动态完整结构 | **必须带 `features=itemOpusStyle,listOnlyfans,opusBigCover,onlyfansVote`**；不带时无正文（退回老式 draw 表示） |
| `x/polymer/web-dynamic/v1/opus/detail` | 长文全文 | 冒号段化 `modules[]`（`MODULE_TYPE_TITLE/AUTHOR/CONTENT/BOTTOM/STAT`）；`CONTENT.module_content.paragraphs` 含 rich 节点/图片段/代码块等；单响应可达 200KB+ |
| `x/polymer/web-dynamic/v1/feed/space` | UP 列表（二期批量） | 需 `get_wbi`；`host_mid + offset + timezone_offset=-480 + features`；每页约 13 条；置顶动态会在首部（按 `pub_ts` 过滤归属日期） |
| `x/v2/reply` | 评论列表 | 已有 `CommentUrls.LIST`，不新增 |

动态 ID 解析规则（`DynamicService._resolve_dynamic_id`）：
- 纯数字 ID / `https://(www|m).bilibili.com/opus/{id}` （忽略 query）；
- `https://t.bilibili.com/{id}` 旧分享链（兼容）；
- `b23.tv` 短链由调用方或二期 GUI 跟随跳转后归一化（与现有视频短链策略一致）。

### 4.2 数据模型：`src/models/dynamic_model.py`

```python
@dataclass
class DynamicAuthor:      # mid, name, face/avatar, pendant{name,image,image_enhance}, decorate{name,card_url}, pub_time, pub_ts, location
@dataclass
class DynamicMedia:       # kind(image|live|emoji|cover), url, width, height, size_kb, ext, local_file, emoji{package_id,id,text,short_name}
@dataclass
class DynamicStats:       # like, comment, forward
@dataclass
class DynamicCard:        # kind(archive|goods|common|reserve|live_rcmd|pgc|courses|music|medialist|article|common_square),
                          # title, desc, jump_url, cover_url, extra(dict 原样保留关键字段)
@dataclass
class DynamicContent:     # title, text(纯文本), blocks: list[dict](见 4.3.2), truncated, full_text_fetched
@dataclass
class DynamicInfo:        # id, type(原始 DYNAMIC_TYPE_*), kind(归一化), url, author, topic, content,
                          # media{images,emojis}, cards[list[DynamicCard]], lottery, vote, stats, forward(DynamicForward|None), raw(dict)
@dataclass
class DynamicForward:     # orig: DynamicInfo | None, deleted: bool, author_mid, archive_dir(落盘相对路径)
@dataclass
class DynamicDownloadResult:  # path(动态目录), md_path, cached, media(list[DownloadResult]), comments_path,
                              # forwarded(list[DynamicDownloadResult]), failures(list[str]), warnings(list[str])
```

`kind` 归一化枚举：`word / draw / article / forward / archive / live / pgc / courses / music / medialist / common / unknown`，由 `item.type` + `major` 非空子对象 + `additional` 联合判定（见 4.3.1）。

### 4.3 解析规则

#### 4.3.1 类型判定（`major` 是联合体，所有键都在，只有一个是非空）

| 判定 | 结论 | 可下载物 |
|---|---|---|
| `major.opus` 非空（title/summary/pics） | 现代主路径：纯文字/图文/专栏都走它 | summary.text + rich nodes + pics |
| `major.draw` 非空（老式） | 老式图文（detail 不带 features 时的表示） | `items[].src` |
| `major.archive` 非空 | 视频卡 | 封面 + 元数据（bvid/title/stat/duration） |
| `major.common` 非空 | 通用卡/装扮卡 | 封面 + 元数据 |
| `major.article / music / medialist / ugc_season / live / live_rcmd / pgc / courses` | 对应卡片 | 封面 + 元数据 |
| `item.orig` 非空 | 转发 | 转发语 + 递归 |
| `item.type == DYNAMIC_TYPE_DELETED`（或 orig 无 modules） | 已删除 | 占位说明 |

正文取值优先级：`module_dynamic.desc`（老式）→ `major.opus.summary`（新式）。`has_more=true` 时调 `opus/detail` 取全文（用 paragraphs 重渲染，见 4.3.3）。

#### 4.3.2 富文本节点 → blocks 映射（`desc.rich_text_nodes` / `summary.rich_text_nodes`）

节点公共字段：`{text, orig_text, type, jump_url, icon_url, rid, emoji, goods, style, pics, video}`。

| 节点类型 | blocks.type | 渲染 |
|---|---|---|
| `TEXT` | `text` | 原文（保留换行） |
| `AT` | `mention` | `@{text}`，附 jump_url |
| `EMOJI` | `emoji` | md 内联图片引用 `![短名](相对路径)`；同时生成下载任务 |
| `TOPIC` | `topic` | `#{text}#` |
| `WEB` | `link` | `[text](jump_url)`（text 常为"网页链接"） |
| `LOTTERY` | `lottery` | `【互动抽奖】` + rid（参与入口=原动态链接） |
| `VOTE` | `vote` | 选项文本（降级） |
| `GOODS` | `goods` | 商品名 + jump_url |
| `BV`/`AV`/`VIDEO` | `video` | 标题/`video` 字段 + 链接 |
| 未知类型 | `unknown` | 原样 text，raw 保留 |

#### 4.3.3 长文全文（opus/detail）

`MODULE_TYPE_CONTENT.module_content.paragraphs[]` 的 `para_type`：`1`=文本段（`text.nodes[]`，`TEXT_NODE_TYPE_WORD` 含 `style.bold/italic/heading`，`TEXT_NODE_TYPE_RICH` 含 rich 节点）、`2`=图片段（`pic.pics[]`）、以及 `line/list/code/blockquote/link_card/heading` 等。渲染为 Markdown：标题 `#`、列表 `-`、代码 ``` 包裹、引用 `>`、分割线 `---`、图片引用本地 `images/`。

#### 4.3.4 卡片与附加卡

- `additional.type`：`GOODS / COMMON(游戏、装扮等) / RESERVE(预约，desc3 可能是"预约有奖"链接) / UGC / MATCH / VOTE / UPOWER_LOTTERY`；每个子对象都下载封面（若有）到 `_assets/covers/`（经账本取号），其余字段原样进 `dynamic.json`。
- 视频卡 `major.archive`：封面 → `_assets/covers/{动态发布日期}_{自增号}.{ext}`；md 渲染 bvid/标题/时长/统计/链接。
- 直播预约 `additional.reserve`：标题/时间/预约数/有奖信息。
- 商品 `additional.goods.items[]`：每个 item 的 `cover` 下载，名称/价格/链接进 md。

#### 4.3.5 转发递归

- `orig` 是完整嵌套动态 → 构造子 `DynamicService.download_dynamic(orig_id, depth+1)`，写入原作者目录；
- 主动态 `dynamic.md` 中渲染引用块：原动态文本 + **相对路径**指向原作者目录（整棵 `output/dynamic/` 一起移动仍有效）；
- `max_forward_depth=3`：超深或循环（祖先 ID 集合判重）时停止并警告；
- 原动态已删除：引用块渲染"原动态已删除"。

### 4.4 缓存与目录层

- 目录/序号/缓存判定流程见 2.1–2.3，媒体编号见 2.6。实现要点：
  - `AssetIdAllocator`（`src/util/asset_allocator.py`）：预分配文件名 + 锁 + O_EXCL 占位 + `index.json` 账本读写；images/covers 各一个实例；
  - `dynamic_id.txt`：内容为纯 ID（`1250464970768908294\n`）；写入走 `tempfile` + `os.replace`；
  - `_assets/manifest.json`：`{"avatar": {"file": "avatar_洛天依.png", "url": "...", "updated_at": "..."}, "emojis": {"10238/145972": {"file": "emojis/10238/送花.gif", "url": "...", "text": "[...]"}}}`；URL 未变且文件存在 → 跳过；
  - 表情短名：`text` 去方括号后取最后一个 `_` 之后片段（`[洛天依14周年·纯蓝幻乐 动态表情包_送花]` → `送花`；`[doge]` → `doge`）；同包短名冲突时追加 `_{emoji_id}`；
  - 写盘顺序：媒体 → `dynamic.md` → `raw.json` → `dynamic.json` → **最后** `dynamic_id.txt`。

### 4.5 下载流程（单条）

```
resolve ID → BiliSession detail(features) → 解析 DynamicInfo
  → 缓存判定（2.3）→ 命中则 cached 返回
  → 建目录 → 媒体任务构建（单线程预分配文件名，见 2.6）：
       正文图片（pics，含 live_url）→ _assets/images/，经账本取号
       内联表情（去重后的 emoji 节点）→ _assets/emojis/{package_id}/（跨动态复用）
       作者资源（avatar/pendant/decorate）→ _assets/（manifest 判缓存）
       卡片封面 → _assets/covers/，经账本取号
  → BatchProgress 串行下载（任务已绑定唯一路径，失败进 failures 不中断）
  → 转发递归（写原作者目录）
  → 评论：get_comments_by_oid(comment_id_str, comment_type, sort="hot", max_count=20) → comments.json
  → 渲染 dynamic.md / dynamic.json / raw.json
  → 最后写 dynamic_id.txt
```

- 一期媒体下载**串行**（单条资源量不大、风控友好）；进度用 `BatchProgress(n=媒体数)`，`pics[].size`（KB）可用于预估总量；
- 单文件失败重试交给 `download_stream`（内置 3 次 + `.part` 续传）；最终失败记入 `failures` 并继续其余文件；
- 评论接口失败不阻断整体（记 warning，md 注明"评论获取失败"）。

## 8. 风险与待定项

| 项 | 说明 | 对策 |
|---|---|---|
| 动态内容可编辑 | 用户编辑后 md/json 与旧媒体可能不一致 | 目录名不含摘要（已规避）；`force=True` 刷新；不加自动清理 |
| 序号语义混用 | 单条补下序号≠发布序（已接受） | 批量（二期）排序编号保证主场景为发布序 |
| 长文接口体量大 | `opus/detail` 单响应可达 200KB+，段落 300+ | 仅 `has_more=true` 时请求；raw.json 原样存储 |
| 匿名可见性 | 部分动态需登录/仅粉丝可见；`feed/space` 匿名可用但有限制 | 导航到 `BiliAuthError` 时提示登录；二期批量接 `RiskGate` |
| 表情包名解析 | 一期只用节点 text 短名，不调 EmoteService | 若需要包名，二期用 `EmoteService.get_packages` 补 |
| 投票/UPOWER_LOTTERY 无实测样本 | 字段可能超出本计划预期 | raw.json 兜底 + 未知节点降级为 unknown，不中断 |
| `b23.tv` 短链 | SDK 一期不解析 | 调用方传 opus 链接或 ID；GUI 二期按现有短链策略处理 |
| 自增编号的空洞与多实例 | 删除文件不回退编号（唯一性优先）；同 UP 两实例并发写账本为 last-wins | 默认按单实例设计；后续如需多实例再加文件锁（O_EXCL 占位已兜底文件撞名） |

细节确认点（评审时请留意）：第 3 章唯一的侵入式改动（`ReplyService.get_comments_by_oid` 公共化）、第 6 章第 1 条 fixtures 入库（纯 API JSON、无媒体文件）。
