# BiliTools 桌面版前端实施计划（PySide6）

> 状态：计划稿（v2，已纳入 9 条设计约束）。本文只描述设计与实施细节，不包含具体代码。
> 适用范围：Windows 桌面端。已放弃手机端与 PyQt6 路线。

## 1. 背景与目标

- 复用现有分层 SDK（`src/`），在其上构建一个 **PySide6 桌面 GUI**。
- 目标是"正统的电脑软件"：独立窗口、原生控件、可打包为单 exe，**不是浏览器，也不依赖命令行**。
- 界面结构（自上而下）：顶部软件名 + 最小化/关闭 → 功能切换（下载/登录/设置）→ 主体内容页。

## 2. 设计约束（用户决策，本次必须遵守）

| # | 约束 | 落地位置 |
|---|------|----------|
| 1 | **未登录不下载**：下载前强制检查登录，未登录则阻止并引导去登录页 | §5.7 登录门禁 |
| 2 | **允许小范围修改 `src`**，但不得影响原有调用方式（只加可选参数/新增方法） | §10 |
| 3 | **界面不直接写在 `frontend/` 下**，放 `frontend/` 的子文件夹（为将来其他前端预留） | §3 目录结构 |
| 4 | **支持深色/浅色模式**，界面样式尽量全部自定义 QSS（参考 `frontend/old/config.py` 样式），避免不同用户观感差异大 | §11 主题设计 |
| 5 | **下载支持多次点击同一按钮**（每次点都开新线程）；**内容不变不重复下载**，参数变了才新提交 | §5.6 下载去重 |
| 6 | **单个视频的实时百分比刷新在下载区域**（覆盖式、不进日志）；**右侧日志只记大进度**（单个下好、批量到第几个），追加式 | §5.2 任务进度区 / §6 |
| 7 | **所有输入都支持「传正确参数」或「传完整 URL」两种方式** | §5.3 输入归一化 |
| 8 | **登录检查时机**：每次应用启动时 + 下载彻底失败时 | §7 |
| 9 | **任何时候都不允许闪退**；报错同时写到界面和日志文件 | §9 异常安全 |

## 3. 总体架构与目录结构

```
src/（现有 SDK，可小范围增强）
   └── services/          VideoService / LoginService / FavService / UserService …
           ↑ 直接调用（下载方法在 QThread 中执行）
frontend/                 多个前端的容器
   ├── old/               【保留勿动】旧 PyQt6 代码（仅作参考）
   ├── __init__.py        包声明（frontend 作为包容器）
   └── pyside6/           本方案：PySide6 桌面前端（全部代码在此）
       ├── __init__.py
       ├── __main__.py    GUI 入口（python -m frontend.pyside6）
       ├── app.py         创建 QApplication、安装全局异常钩子、装配主窗口
       ├── main_window.py 主窗口：标题栏 + 导航栏 + 内容区（QStackedWidget）
       ├── title_bar.py   自定义标题栏（软件名 + 最小化/最大化/关闭 + 主题切换）
       ├── nav_bar.py     功能切换（下载/登录/设置）
       ├── signals.py     全局信号总线（AppSignals 单例）
       ├── logs.py        日志管线（logging.Handler + stdout 重定向 + 分类器 + 日志文件）
       ├── settings.py    设置读写（JSON 持久化）
       ├── theme.py       深色/浅色主题：调色板 token + QSS 生成 + ThemeManager
       ├── utils.py       输入归一化（bv/av/URL、fid、sid、mid）
       ├── pages/
       │   ├── download_page.py   下载页
       │   ├── login_page.py      登录页
       │   └── settings_page.py   设置页
       ├── widgets/
       │   ├── log_widget.py      彩色里程碑日志控件
       │   ├── login_card.py      登录状态卡片（头像/昵称/mid）
       │   ├── download_panel.py  左侧下载输入面板
       │   └── task_progress_panel.py  实时任务进度区（QProgressBar 列表）
       └── workers/
           ├── download_worker.py   下载线程
           ├── download_manager.py  任务去重 + 并发管理
           ├── login_worker.py      登录/状态查询线程
           └── progress_adapter.py  BatchProgress 兼容对象 → Qt 信号
```

- **分层原则**：`frontend/pyside6/` 只调用 `src/` 的服务接口；下载/网络一律在后台线程，UI 线程只收信号刷新界面。
- **GUI 入口**：`python -m frontend.pyside6`；根目录 `main.py`（命令行）保持不动。
- 未来若再做其他前端（如 web），在 `frontend/` 下新增平级子目录即可，互不干扰。

## 4. 主窗口结构

```
┌────────────────────────────────────────────────┐
│ ☰ BiliTools            [🌙]   ─  □  ✕  ← 标题栏
├────────────────────────────────────────────────┤
│  下载  │  登录  │  设置                          ← 导航栏
├────────────────────────────────────────────────┤
│                 主体（QStackedWidget）          │
│        DownloadPage / LoginPage / SettingsPage  │
└────────────────────────────────────────────────┘
```

- **窗口形态**：无边框窗口（`Qt.FramelessWindowHint`）+ 自定义标题栏，用于完全掌控顶部样式。
  - 左侧：软件名（可带小图标）；右侧：主题切换按钮（🌙/☀）、最小化、最大化(还原)、关闭。
  - 需处理：标题栏空白拖拽移动、双击最大化/还原、关闭时若有下载任务需确认。
  - 兜底：若个别环境无边框表现不佳，退回"原生标题栏 + 窗口内顶部工具条"。
- **导航栏**：`QTabBar`（或自绘按钮组）切换 `QStackedWidget`；当前页高亮；右侧可放"运行中任务数"小标签。
- **全局主题**：`ThemeManager.apply(app)` 用统一 QSS 覆盖全部控件（见 §11），切换主题即时生效并持久化。

## 5. 下载界面（DownloadPage）

```
┌───────────────┬──────────────────────────────────┐
│ 保存目录: […output/video]  [浏览…]  [队列 x]     │
│ ┌───────────┐ │ ┌────────────────────────────┐  │
│ │视频BV 收藏夹 │ │ │ 登录状态卡片               │  │
│ │合集   UP主  │ │ │ (头像) 昵称 mid=xxx [刷新] │  │
│ ├───────────┤ │ ├────────────────────────────┤  │
│ │ 输入 + 选项 │ │ │ 彩色里程碑日志（追加式）     │  │
│ │ [下载]     │ │ └────────────────────────────┘  │
│ ├───────────┤ │                                  │
│ │ 任务进度区  │ │  ← 实时百分比（覆盖式）          │
│ │ [bar] 45%  │ │                                  │
│ └───────────┘ │                                  │
└───────────────┴──────────────────────────────────┘
```

### 5.1 左侧：下载输入面板（download_panel.py）

顶部一行：**保存目录**（默认 `output/video`，可被设置页默认值覆盖，此处可临时改，带"浏览…"）。

**来源页签**（QTabWidget）：`视频BV` / `收藏夹` / `合集` / `UP主`，各页签输入不同（都支持参数或完整 URL，见 5.3）：

| 页签 | 输入 | 归一化目标 |
|------|------|-----------|
| 视频BV | BV号 / av号 / 完整链接 | bvid |
| 收藏夹 | media_id 或收藏夹链接 | media_id |
| 合集 | 合集内视频 BV / 链接，或 sid / 合集 URL | (bvid 或 sid+mid) |
| UP主 | mid 或空间链接 | mid |

**选项（所有页签共用）**：
- **范围**：仅 `视频BV` 页签显示 `○ 单P（[n]） ○ 全部P`（单P 时出现 QSpinBox）；其余页签语义即整批，隐藏/禁用该选项。
- **类型**：`● 视频（含音频） ○ 仅音频`。约定：**"视频"永远=视频+音频合成，UI 不提供"仅视频无声"**（SDK 的 `media_type="video"`/`download_video` 不暴露）。
- **清晰度**：下拉（`VideoQuality.display_name`），默认取设置页默认值（默认 4K）。
- **下载按钮**：`下载`。每次点击即提交一个新任务（可反复点击并发下载，见 5.6 去重）。

### 5.2 左侧：任务进度区（task_progress_panel.py）—— 实时百分比，覆盖式

- 位置：输入面板下方（见上图）。展示**每个运行中任务一行**：
  `任务描述 | 清晰度标签 | [QProgressBar] | 45% | 阶段文本（下载中/合成中/等待队列）`
- **数据来源**：`ProgressAdapter`（见 §6.3）把 SDK 的字节进度回调（`update/add/make_stream_callback`）转成信号 → 直接 `setValue()`/`setText()` **就地覆盖刷新**，不产生任何日志行。
- ffmpeg 合成阶段无字节数 → 进度条置为不定态（busy），阶段文本"正在合成…"。
- 任务结束：该行短暂显示"完成 ✓"后移除（或进入"最近完成"折叠列表）；失败显示红字"失败"后保留至手动清除。
- **与日志的分工（约束 #6）**：百分比=覆盖式（进度区）；里程碑（单个文件下好、批量第 i/n 个）=追加式（右侧日志）。两者互不占用。

### 5.3 输入归一化 —— 所有入口支持「参数 或 完整 URL」（约束 #7）

`frontend/pyside6/utils.py` 提供以下函数，统一把原始输入规整为**规范 id**，供任务去重 key 使用；解析失败返回错误信息（由调用方红色记入日志，不创建线程）：

| 函数 | 接受的输入 | 规则 |
|------|-----------|------|
| `normalize_bvid(raw)` | BV/bv 号、av/AV 号、视频链接 | ①BV 开头且 12 位原样返回；②`av`+数字走 `src.util.bvid.av2bv`；③链接先从字符串取 `BV[0-9a-zA-Z]{10}`，取不到再 `requests.get(allow_redirects=True)` 后从最终 URL 提取 |
| `normalize_fav(raw)` | 纯数字 media_id、收藏夹链接 | 直接透传（SDK `_resolve_media_id` 已支持 URL）；数字校验为纯数字 |
| `normalize_season(raw)` | BV/视频链接 → bvid；纯数字 → sid；合集 URL → 提取 sid（可选 mid） | 合集 URL 形如 `space.bilibili.com/<mid>/channel/collectiondetail?sid=<sid>`（新旧两种路径均匹配）；返回 `("bvid", bvid, None)` 或 `("sid", sid, mid_or_0)` |
| `normalize_mid(raw)` | 纯数字 mid、空间链接 | 直接透传（SDK `_resolve_mid` 已支持 URL）；链接提取 `space.bilibili.com/<mid>` |

> 归一化在**提交前**完成：既保证去重 key 稳定，也让"参数写错/链接无效"这类错误在开线程之前就红色报出来。

### 5.4 右侧上：登录状态卡片（login_card.py）

- 数据：`LoginService.get_login_state()`（`LoginUser`：is_login / uname / mid / face）。
- 已登录：圆形头像（`face` 经 `QNetworkAccessManager` 异步下载，缓存 `assets/cache/face_{mid}.png`）+ 昵称 + `mid=xxx`。
- 未登录：灰头像占位 + "未登录，请前往登录页扫码"（同时可点击跳转登录页）。
- 附"刷新"按钮；登录成功/退出/下载失败重检后自动刷新。

### 5.5 右侧下：彩色里程碑日志（log_widget.py）

只记录**大进度里程碑**（追加式）：
- 任务开始（"开始下载：BV… / 收藏夹「…」"）；
- 批量进度（深蓝："正在下载 第 i/n 个：name"、"已下载 3/24 个视频"）；
- 单个完成（绿加粗："下载完成：path"；命中缓存 → "已存在，跳过：path"）；
- 失败（红加粗）、警告（橙）、普通信息（黑）。
- 颜色规范与消息来源见 §6。

### 5.6 下载去重（约束 #5）

`DownloadManager` 维护任务集，以**任务 key** 判重：

- key = `(来源类型, 归一化输入, 范围[单P:n/全部], 类型[视频/音频], 清晰度, 保存目录)`。
- **提交时**：key 已存在于"运行中+队列" → 不新建线程，日志提示（深蓝）"相同任务已在进行：<描述>"；key 不在 → 立即新开 `DownloadWorker` 线程并注册。
- **任务结束**：从集合移除，因此任务完成后再点会重新提交（此时由 SDK 的本地缓存判断直接"跳过下载"，见下）。
- **双层去重**：
  1. 运行期 key 去重（防重复线程）；
  2. SDK 下载前的**本地文件缓存判断**（`_find_downloaded_file` → 命中返回 `cached=True`，UI 绿字"已存在，跳过下载"）——所以"内容不变"的重复请求不会真的重新下载。

### 5.7 登录门禁（约束 #1）

- **提交下载前**先查登录（用启动时缓存的结果 + 快速复查 `has_valid_session`）：
  - 已登录 → 正常进入下载流程；
  - 未登录 → **阻止下载**，日志橙色提示"未登录，无法下载，请先扫码登录"，界面弹出提示并自动切到/高亮登录页（或提供"去登录"按钮）。
- 未登录时下载按钮同时置灰，鼠标悬停提示"请先登录"。
- 下载**彻底失败**（见 §9/§7）时触发登录重检：若发现登录失效，日志红色提示"登录状态已失效，请重新登录"并引导。

## 6. 日志系统

### 6.1 颜色规范（主题感知）

| 类别 | 浅色 | 深色 | 样式 | 示例 |
|------|------|------|------|------|
| 普通信息 | #212121 | #E0E0E0 | 常规 | "开始下载：BV…"、"正在用 ffmpeg 合成…" |
| 批量/大进度 | #1a4f8b | #7fb3e8 | 常规 | "正在下载 第 3/24 个：xxx.mp4"、"已下载 3/24 个视频。" |
| 警告 | #b35c00 | #e59a3d | 常规 | 风控重试、视频不可见跳过、未登录阻止 |
| 报错 | #c62828 | #ff6b6b | **加粗** | 下载失败、异常栈、ffmpeg 未安装 |
| 完成 | #2e7d32 | #6fd17a | **加粗** | "下载完成：xxx.mp4"、"收藏夹「…」全部下载完毕。" |

> 语义色在深色模式下提高亮度保证可读性；"普通信息"用主题前景色（浅色=黑、深色=浅灰）。
> 默认带时间戳前缀 `[HH:MM:SS]`（设置页可关）。

### 6.2 三类消息来源 → 一条信号通道

统一入口：`AppSignals.log_message = Signal(LogCategory, str)`，`LogWidget` 订阅后按类别着色。

1. **SDK `logging` 记录** → 前端 `logging.Handler` 挂到 `src` logger 树，按 level 转发（INFO→普通、WARNING→橙、ERROR→红加粗）。
2. **SDK `print()` 输出** → 启动时替换 `sys.stdout/stderr` 为重定向对象，默认普通色，用于捕获 `_report_bvid_download` 等 print。
3. **下载线程结构化事件**（主要着色来源）→ `DownloadWorker`/`ProgressAdapter` 显式发信号：
   - `batch_start(i, n, name)` → 深蓝："正在下载 第 i/n 个：name"；
   - `item_done(result)` → 绿加粗（含缓存命中提示）；
   - `error(msg)` → 红加粗；
   - `batch_finished(label, ok, fail)` → 绿加粗："合集「…」下载完毕（成功 x / 失败 y）。"。

**分类器（补充规则）**：对来源 1、2 的文本用稳定正则二次着色，覆盖 SDK 内部非结构化的进度行：
- 匹配 `已下载 \d+/\d+ 个视频` → 深蓝；
- 匹配 `Traceback|Error|失败` → 红加粗（兜底）；
- 其余维持默认。

### 6.3 进度 vs 日志的分工（约束 #6）

- **字节级实时进度** → 任务进度区（§5.2），覆盖式，**绝不进日志**。
- **里程碑/大进度** → 日志，追加式。
- 桥接：`ProgressAdapter` 实现 SDK `BatchProgress` 的鸭子接口（`__init__(n,label,display)`、`start/set_quality/add/update/status/finish/make_stream_callback/iter_count`），内部不 print，改发两类信号：
  - 字节进度 → `progress_changed(done, total)` → 进度条（覆盖）；
  - 里程碑 → `batch_start/item_done/batch_finished` → 日志（追加）。
  该对象作为 `progress=` 传给 SDK 下载方法（SDK 改动见 §10）。

### 6.4 复制与操作

- 只读富文本 `QPlainTextEdit`：**选中即 Ctrl+C**（原生支持）。
- 工具条：`复制全部` / `清空`；右键菜单含"复制选中/复制全部/清空"。
- 新日志自动滚动到底；设置项"最大行数"（默认 1000）超出裁旧。

### 6.5 持久化日志文件（约束 #9 的一部分）

- `logging.FileHandler` 写 `output/logs/bilitools.log`，用 `RotatingFileHandler`（如 1MB × 3 份）。
- **所有消息（含报错）同时进界面日志和日志文件**；文件里额外带时间戳与级别，便于崩溃后排查。
- 程序崩溃瞬间的堆栈由全局异常钩子（§9）兜底写入该文件。

## 7. 登录界面与登录检查（LoginPage / LoginWorker）

```
┌───────────────────────────────┐
│        扫码登录 B 站账号        │
│         ┌─────────┐            │
│         │ 二维码图 │            │
│         └─────────┘            │
│  状态：请用哔哩哔哩 App 扫码     │
│        [重新生成]               │
│  [已登录：昵称 (mid)] [退出登录] │
└───────────────────────────────┘
```

- **流程**（不阻塞 UI）：
  1. `LoginService.generate_qr()` → `(url, qrcode_key)`，`qrcode` 库生成图转 `QPixmap` 显示；
  2. 后台轮询线程按 `interval=1s` 调 `poll(qrcode_key)`，状态码映射文案实时显示（86101 未扫码 / 86090 已扫码待确认 / 86038 失效 / 0 成功）；
  3. 成功 → 保存 cookie 并 `BiliCookies.refresh()`，更新登录卡片，绿字"登录成功：昵称"；
  4. 超时/失效 → 提示并可"重新生成"。
- **登录检查时机（约束 #8）**：
  1. **应用启动时**：后台 `LoginWorker` 查一次 `get_login_state()`，刷新登录卡片（未登录不弹窗，仅状态显示 + 门禁拦截）；
  2. **下载彻底失败时**：下载线程遇到致命错误（风控放弃、`-101 未登录`、权限类）→ 触发登录重检；若已失效，红字提示并引导重新登录（若恢复则自动刷新卡片）。
- **保存 cookie**：`poll()` 只返回状态码、丢弃了 `set-cookie`。方案：新增公开方法 `LoginService.poll_full(qrcode_key) -> (code, set_cookie)`（§10），或直接用内部 `_poll_once`。
- "退出登录"：删除/清空 cookie 文件并刷新缓存，日志提示。

## 9. 线程、并发与异常安全（约束 #5、#9）

### 9.1 并发模型

- 每个任务一个 `DownloadWorker(QThread)`，内部自建 `VideoService`（独立 `BiliSession`，避免跨线程共享会话），在 `run()` 中调用下载方法，通过信号上报。
- **多次点击 → 并发多线程**（约束 #5）：`DownloadManager` 不设硬并发上限，只管去重（§5.6）。同一任务内 SDK 仍串行并自带防风控 sleep。
  - 提示：高并发会提高触发风控的概率；SDK 对 `-412/-403` 已有随机退避重试，日志会橙色提示。若实际使用风控频繁，后续可加"最大并发数"设置项（默认不限）。

### 9.2 异常安全（永不闪退）

四层防护：

1. **全局钩子**（`app.py` 启动即装）：
   - `sys.excepthook` / `sys.unraisablehook` → 红色写入界面日志 + 日志文件，程序继续运行；
   - `qInstallMessageHandler` → Qt 侧 warning/critical 同样接入日志管线。
2. **线程内兜底**：每个 `QThread.run()` 整体 `try/except`，异常不抛出线程（否则 Qt 会打印并可能终止进程），统一 `emit error(msg)`。
3. **下载方法级**：单文件内部失败由 SDK `_execute_batch_download` 处理（跳过不可见视频、风控重试）；致命错误由 worker 捕获记红字，并触发登录重检（§7）。
4. **UI 槽函数**：信号连接统一经一个安全包装（`connect_safe`），槽内异常被捕获记入日志，避免单个回调错误拖垮界面。

> 验收口径：任一步骤出错，界面不闪退、报错可见（界面红字 + 日志文件双份），其余功能不受影响。

## 10. SDK 小改动（约束 #2：允许，但向后兼容）

> 原则：只**增加可选参数/新增方法**，不改任何现有调用语义；改动集中在 `src/services/video.py` 与 `src/services/login.py`。

1. **`VideoService.download_fav` / `download_up` 增加 `progress` / `progress_cb` 可选参数**：透传给内部 `download_all_pages`。当前这两个方法不接受进度对象，UI 无法拿到"第 i 个视频/共 n 个"的精确事件。（约 3 行/处）
2. **`LoginService` 新增公开方法 `poll_full(qrcode_key) -> tuple[int, str]`**：返回 `(code, set_cookie)`，供登录页保存 cookie（不动 `poll()`）。
3. （视需要）**`VideoService.download_season` / `download_all_pages` 已支持 progress，无需改动**；如需"合集 URL 直接进"也由前端 `normalize_season` 解析后调现有参数，不必改 SDK。

## 11. 主题设计（深色/浅色，自定义样式；约束 #4）

### 11.1 设计思路

- 参考 `frontend/old/config.py` 的样式模式（圆角按钮 + 彩色边框 + hover/pressed 变体、输入框圆角 + hover 变色、下拉框同风格、天依蓝 `#66CCFF` 主强调色、白/浅蓝背景、12/14/16px 文本层级），**抽象成调色板 token + QSS 模板**，深浅两套主题各自生成一套样式，全应用统一应用，**不依赖操作系统原生观感**。
- `theme.py` 三个部分：
  1. **调色板 token**（浅色/深色各一组）：`window_bg / panel_bg / card_bg / text / text_dim / accent(天依蓝) / accent_hover / border / border_hover / input_bg / input_border / hover_border / danger / success / progress_bg / progress_fg / titlebar_bg / nav_active / nav_inactive / scrollbar_*` 等；
  2. **QSS 生成器**：从 token 拼出覆盖 QPushButton / QLineEdit / QComboBox / QTabBar / QProgressBar / QPlainTextEdit / QLabel / QScrollBar / QMenu / QMessageBox 等的样式表；
  3. **ThemeManager**：维护当前主题（`light` / `dark` / `system`），`apply(app)` 设置 `QApplication.setStyleSheet()`，切换时发信号让个别需要重绘的控件（如日志配色）刷新。
- 主题模式存设置；`system` 跟随 Windows 深浅色（高 DPI 下用 `Qt` 的配色判断或监听系统主题变更）。

### 11.2 控件样式要点（从旧 config 迁移）

| 控件 | 旧样式参考 | 新实现 |
|------|-----------|--------|
| 按钮 | `BTN_ARONA`/`BTN_BLUE_PURPLE`（圆角 6px、2px 边框、hover/pressed 变体） | token 化的 QPushButton 样式，深浅主题各一套配色 |

| 背景 | `Background_css.WHITE` / `LIGHT_BLUE`（天依蓝 20% 透明） | `window_bg` / `panel_bg`，深色主题为深灰底 |

- 不做手机端 / 跨平台（Windows 优先）。
