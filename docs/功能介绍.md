# BiliTools 功能介绍

BiliTools 由三部分组成：

- **后端 SDK**：`src/services/` 面向业务场景封装 B 站 API，返回 dataclass 或 `DownloadResult`。
- **桌面 GUI**：`frontend/pyside6/` 负责输入解析、任务调度、线程、进度和日志，不在界面线程直接发下载请求。
- **命令行/示例**：`main.py` 和 `examples/` 下按功能拆分的示例复用同一套 service，不复制 API 逻辑。

本文给出完整功能、主要参数、数据流和前端使用方法。代码中的 API URL、鉴权参数和原始响应示例仍以各 service 的 docstring 为准；本文解释它们如何串起来。

---

## 1. 总体架构与数据流

```text
用户输入
  ├─ CLI：规范 BV/fid/sid/mid 后直接调用 service
  ├─ GUI：utils.py 先本地归一化；短链在 DownloadWorker 中跟随跳转
  └─ examples：直接演示 service 调用
        │
        ▼
src/services/
  ├─ 组装业务参数、选择 API URL、组织分页/批量流程
  ├─ 把 API data 转成 src/models/ 中的 dataclass
  └─ 把下载任务交给 src/util/（断点续传、命名、ffmpeg、进度）
        │
        ▼
src/api/BiliSession
  ├─ 从当前 cookie 路径读取 BiliCookies
  ├─ 注入 User-Agent / Referer / Cookie
  ├─ 请求 JSON API，检查 HTTP 状态和 code
  ├─ 传输层错误自动重试；业务错误抛 BiliError
  └─ 只把响应的 data 字段返回给 service
        │
        ├─ src/api/auth.py：playurl 等接口需要时追加 wts/w_rid
        ├─ src/models/：VideoInfo、DashStreams、HistoryPage 等稳定数据对象
        └─ src/util/downloader.py：媒体字节 → 本地文件 → DownloadResult
```

### 1.1 视频下载的完整链路

以 `VideoService.download_video_with_audio(bvid, page=1, quality=...)` 为例：

1. **查信息**：调用 `VideoUrls.VIEW`（`/x/web-interface/view`），拿到标题、封面、作者、统计、`pages` 和 `cid`，转换为 `VideoInfo`。
2. **定位分P**：根据 `page` 在 `VideoInfo.pages` 中找到目标 `VideoPage`；`cid` 是播放流接口的鉴权参数。
3. **请求播放流**：组装 `bvid/cid/qn/fnval/fourk/...`，调用 `get_wbi()` 原地追加 `wts/w_rid`，再请求 `VideoUrls.PLAY`（`/x/player/wbi/playurl`）。
4. **解析 DASH**：从 `data.dash.video/audio` 构造 `VideoStream` 与 `AudioStream`；`DashStreams` 自动按清晰度/码率排序，`pick_video()` 精确匹配目标档位，找不到时回退到最高可用档。
5. **检查缓存和 ffmpeg**：最终文件存在且非空则返回 `DownloadResult(cached=True)`；否则预检系统 ffmpeg 或 `imageio-ffmpeg`。
6. **下载两条流**：视频与音频分别进入临时目录，`download_stream()` 使用会话请求头并支持 Range 断点续传。
7. **合成和返回**：`merge_video_audio()` 调用 ffmpeg 写入最终 mp4；临时文件默认清理，`keep_parts=True` 时移出保留；最终返回路径、大小和缓存状态。

单独下载视频、音频或封面时，前半段信息流相同，只在最后一步分别写入视频流、音频流或封面二进制。

### 1.2 统一异常与前端错误流

`BiliSession` 将接口错误码转换为异常：

| 异常 | 常见原因 | GUI 行为 |
|---|---|---|
| `BiliAuthError` | 未登录或 cookie 失效（如 -101） | 任务失败后提示重新登录并跳转登录页 |
| `BiliRiskError` | 风控（如 -412） | 批量任务退避重试；并发时通知其他线程在下一次取信息前暂停 |
| `BiliForbiddenError` | 访问被拒绝（如 -403） | 按风控类错误处理 |
| `VideoNotFoundError` / `BiliAPIError` | 视频不存在、不可见或其他业务错误 | 单任务显示错误；批量中不可见视频按策略跳过 |
| `FFmpegNotFoundError` | 没有可用 ffmpeg | 在下载流之前直接提示安装，避免白下媒体流 |

## 2. 后端服务完整说明

### 2.1 视频：`VideoService`

#### 基本信息

```python
from src.services import VideoService

service = VideoService()
info = service.fetch_info("BV1ov42117yC")
print(info.title)
print(info.owner.name, info.owner.mid)
print(info.stat.num_view, info.stat.num_dm, info.stat.num_reply)
print(info.pages)       # VideoPage 列表：page/cid/part/duration/dimension
print(info.season)      # 可选 VideoSeason，包含合集 episodes

info = service.fetch_info_with_tags("BV1ov42117yC")
print(info.tags)
```

调用关系：`fetch_info()` → `VideoUrls.VIEW` → `BiliSession.get()` → `VideoInfo.from_view_json()`；`fetch_info_with_tags()` 再调用 `VideoUrls.TAG` 并把 `tag_name` 列表写回同一个 `VideoInfo`。

#### 单P、分P和媒体类型

```python
from src.models import VideoQuality

# 视频流，不含音频
video = service.download_video("BV1ov42117yC", quality=VideoQuality.P1080)
# 只下载音频，适合本地缓存听歌
audio = service.download_audio("BV1ov42117yC")
# 视频 + 音频，使用 ffmpeg 合成一个文件
result = service.download_video_with_audio("BV1ov42117yC")
# 指定第 2P；文件名会带 -P02- 和该P标题
result = service.download_video_with_audio("BV1Q43w6QETb", page=2, quality=VideoQuality.P1080)
# 下载全部分P；返回 DownloadResult 列表
results = service.download_all_pages("BV1Q43w6QETb", quality=VideoQuality.P1080)
# 封面：调用 VIEW 得到 pic，再通过 get_raw 下载二进制
cover = service.download_cover("BV1ov42117yC")
```

保存目录通过 `dir` 指定，不传时使用 `VIDEO_OUTPUT_DIR`（默认项目 `output/video/`）。文件名由 `src/util/filename.py` 统一清洗，避免标题中的路径非法字符。

#### 清晰度选择

`VideoQuality` 覆盖 `P360`、`P480`、`P720`、`P720_60`、`P1080`、`P1080_PLUS`、`P1080_60`、`HD4K`、`HDR`、`DOLBY`、`HD8K`。选择是**精确目标**：

```python
# 有 4K + 1080P 时选 1080P，不会因为默认最高而拉到 4K
service.download_video_with_audio("BV1ov42117yC", quality=VideoQuality.P1080)
```

如果接口没有目标档位（未提供或账号无权限），`DashStreams.pick_video()` 回退到最高可用流。4K/HDR/杜比/8K 仍受 B 站账号权限和视频源影响。

#### 统一入口、合集、收藏夹、UP 主

```python
# 自动判断：属于合集则下载整个合集；否则下载该视频全部分P
service.download("BV1ov42117yC")

# 合集：bvid、season_id 二选一；他人合集可传 mid
service.download_season("BV1Q43w6QETb")
service.download_season(season_id=8683221)
service.download_season(season_id=1717000, mid=506925078)

# 收藏夹：fid/media_id；默认视频+音频，mode="audio" 只下载音频
service.download_fav(3953119978)
service.download_fav(3953119978, mode="audio")

# UP 主空间：mid；默认全部投稿
service.download_up(249056021)
service.download_up(249056021, mode="audio")
```

批量链路分别是：

- **合集**：`fetch_season()` → `VideoSeason.episodes` → 每个稿件的 `pages` → 普通媒体下载。
- **收藏夹**：`FavService.get_fav_info()` 得到目录名，`FavService.get_fav_bv()` 得到 BV 列表，再逐个复用 `download_all_pages()`。
- **UP 主**：`list_up_videos(mid)` 翻页得到 BV 列表，`UserService.get_name(mid)` 得到目录名，再逐个复用 `download_all_pages()`。

这些批量方法支持 `threads` 并发、`progress` 进度对象、`progress_cb` 回调和 `account_sessions` 多账号分流。GUI 会先获取列表以初始化总进度，再把列表传回 service，避免同一列表请求两次。

```python
# 并发下载，任务按下标轮询多个已登录会话
from src.api import BiliSession

sessions = [BiliSession(cookie_path="account-a.txt"), BiliSession(cookie_path="account-b.txt")]
service.download_fav(3953119978, threads=2, account_sessions=sessions)
```

#### 缓存、断点续传与风控

- 目标文件按 BV 号和分P序号在输出目录中递归查找，命中后返回 `cached=True`，不再请求播放流。
- `download_stream()` 发现已有半截文件时发送 `Range: bytes=<size>-`；服务器不返回 206 时会丢弃半截文件并从头下载。
- 批量任务遇到 -404/62002 会记录并跳过；-412/-403 会退避重试。
- 并发任务共享 `RiskGate`，一个线程触发风控后，其他线程下一次获取信息前各自随机暂停。

### 2.2 登录与多账号

#### `LoginService`

```python
from src.services import LoginService

login = LoginService()

# 非阻塞：生成二维码，然后由 UI/调用方自行轮询
url, qrcode_key = login.generate_qr()
code, set_cookie = login.poll_full(qrcode_key)

# 阻塞式脚本入口：生成二维码 -> 轮询 -> 保存 cookie
ok = login.qr_login(timeout=60, interval=1, img_show=True)

user = login.get_login_state()
print(user.is_login, user.mid, user.uname, user.face, user.level)
```

生成流程：`QR_GENERATE` 返回 `url/qrcode_key`，`qrcode` 库把 URL 写成 PNG；`QR_LOGIN` 轮询返回状态码；成功响应头的 `set-cookie` 经过 `save_cookie()` 提取 `SESSDATA/bili_jct/DedeUserID` 后保存，并刷新 `BiliCookies` 缓存。

GUI 不直接使用阻塞 `qr_login()`：`QrLoginWorker` 在 QThread 中生成二维码和轮询，成功后把 set-cookie 交给 `AccountManager.handle_login()`。

#### `AccountManager`

```python
from src.services.account import AccountManager

accounts = AccountManager()
print(accounts.list_accounts())
accounts.switch(123456789)       # 设置当前 cookie 路径并清理缓存
accounts.set_default(123456789)  # 下次启动优先使用
accounts.remove_current()        # 删除当前 cookie 和账号条目
```

账号数据流：登录 set-cookie → 解析 mid → 写入 `<cookie_dir>/<mid>/qr_login.txt` → 更新 `accounts.json` → `set_cookie_path()` → `BiliCookies.clear_cache()` → 新会话使用新账号。账号切换不会把 cookie 内容复制到项目目录。

### 2.3 收藏夹与合集查询

```python
from src.services import FavService, ArchiveService

fav = FavService()
info = fav.get_fav_info(3953119978)
bvids = fav.get_fav_bv(3953119978)
print(info.title, info.media_count, bvids)

archive = ArchiveService()
```

### 2.4 表情包：`EmoteService`

```python
from src.services import EmoteService

emote = EmoteService()
packages = emote.get_packages("10239,10238")
print(len(packages))
results = emote.download_packages("10239,10238")
results = emote.download_packages("10239", use_full_name=True)
```

### 2.5 收藏集和主题装扮：`GarbService`

```python
from src.services import GarbService

garb = GarbService()
items = garb.search_items("洛天依")
item = garb.select_search_item("洛天依")  # 同名优先，否则搜索结果第一项

# 下载收藏集默认的封面、卡片图片和卡片视频
results = garb.download_by_keyword("洛天依")

# 只下载指定素材类别
results = garb.download_by_keyword("洛天依", resource_types=["emoji_package", "space_bg"])
```

`search_items()` 调用装扮商城搜索接口；`get_detail()` 根据 `part_id`/条目结构分流到收藏集详情或主题装扮详情；`prepare_resources()` 把嵌套 JSON 展开成 `GarbResource(category, filename_stem, url, media_type)`；下载器再逐个获取 CDN 二进制。收藏集直接保存封面、卡图、卡片视频；主题装扮按动态卡片、表情包、评论装扮、点赞特效、加载动画、进度条、个性主题、空间海报等类别建目录。

### 2.6 装扮统一搜索：`DressupService`

```python
from src.services import DressupService

dressup = DressupService()
items = dressup.search("洛天依")
for item in items:
    print(item.kind, item.display_name, item.as_dict())
```

### 2.7 历史记录：`HistoryService`

```python
from src.services import HistoryService

history = HistoryService()
page = history.get_history_page(ps=20)
print(page.items, page.has_more, page.max, page.business, page.view_at)

items = history.get_history_all(max_iter=5, filter_type="archive", ps=20)
```

`get_history_page()` 调用 `HistoryUrls.CURSOR`，将 `data.list` 转为 `HistoryItem`，把 `data.cursor` 中的 `max/business/view_at` 保留为下一页游标；`get_history_all()` 把游标传回下一次请求直到没有更多或达到 `max_iter`。导出时只把 `archive` 条目整理为 DataFrame，写到 `output/history/<save_name>.xlsx`，可追加并按 BV 去重。

### 2.8 用户、评论、私信和老粉签约

```python
from src.services import ContractService, MessageService, ReplyService, UserService

user = UserService().fetch_info(506925078)
print(user.name, user.num_follower, user.level)

# 以下是写操作，会真实改变账号状态，谨慎执行
rpid = ReplyService().send_reply("测试评论", bvid="BV1ov42117yC")
MessageService().send_msg(receiver_uid=3493133776062465, content="你好")
ContractService().add_contract(up_mid=506925078)
```

- `UserService.fetch_info()` 调用 `UserUrls.CARD`，将 `card` 字段转为 `UserInfo`；不需要 wbi。
- `ReplyService.send_reply()` 将 BV 转 AV，读取 cookie 中的 `bili_jct`，调用评论接口返回 `rpid`。
- `MessageService.send_msg()` 没有传 `sender_uid` 时先调用 `LoginService.get_mid()`，再组装设备 id、时间戳、CSRF 和 JSON 内容发送。
- `ContractService.add_contract()` 组装 `up_mid/source/scene/platform/csrf` 后提交。

写操作需要有效登录、`SESSDATA` 和 `bili_jct`，接口失败会抛 `BiliAuthError`、`BiliRiskError` 或其他 `BiliError`。

## 3. PySide6 前端使用方法

### 3.1 启动与页面

```bash
python -m frontend.pyside6
```

窗口包括：

- **下载页**：视频 BV、收藏夹、合集、UP主、装扮五个来源页签；清晰度、视频/音频、分P范围、保存目录、线程数、多账号分流和任务进度均在此配置。
- **登录页**：后台检查登录状态，生成二维码并轮询；支持登录新账号和退出当前账号。
- **设置页**：cookie 目录、默认下载目录、清晰度、界面缩放、主题、日志和 ffmpeg 检查。

### 3.2 输入解析到下载线程

下载按钮点击后，`DownloadPanel._build_spec()` 生成统一任务字典：

```text
{source, input, scope, page, media_type, quality,
 save_dir, threads, distribute_accounts, desc}
```

规范化规则：

| 页签 | 支持输入 | 传给后端 |
|---|---|---|
| 视频 BV | BV、av、视频 URL、带 `p=n` 的分P URL | `bvid`，可选 `page` |
| 收藏夹 | `fid`、收藏夹 URL | `media_id` |
| 合集 | BV、`sid`、合集 URL | `(kind, season_id, mid)` 或 bvid |
| UP主 | `mid`、空间 URL | `mid` |
| 装扮 | 关键词搜索后勾选条目 | `DressupItem` 字典列表 |

本地正则或 BV/AV 转换无法解析的 b23.tv 短链不会在 UI 线程发网络请求，而是建立 `pending_resolve=True` 的任务；`DownloadWorker._resolve_pending()` 在工作线程里跟随跳转并重新归一化。

### 3.3 任务调度和进度

`DownloadManager.submit(spec)` 首先检查登录门禁和任务去重，然后为每个任务创建一个 `DownloadWorker(QThread)`。worker 内部：

1. 创建 `VideoService` 或装扮相关 service；
2. 根据 `source` 分流，并把 GUI 预取的 BV 列表/合集结构传给后端，避免重复 API 请求；
3. 用 `ProgressAdapter`/`ParallelProgressAdapter` 把 service 的字节回调转换成 Qt `progress/phase/done` 信号；
4. 将结果摘要写入日志并通知任务完成；
5. 根据异常类别决定是否跳转登录页或提示重试。

视频任务示例：

```text
DownloadPanel 规范化输入
  → DownloadManager.submit(spec)
  → DownloadWorker.run()
  → VideoService.download_*()
  → BatchProgress/ProgressAdapter
  → worker.progress / worker.phase / worker.done
  → TaskProgressPanel + LogWidget
```

### 3.4 各页签的操作步骤

#### 视频 BV

1. 粘贴 BV/av/URL；链接中存在 `p=2` 时界面自动选择「单P」并填入 2，用户仍可手动改为「全部P」。
2. 选择「视频（含音频）」或「仅音频」。
3. 「全部P」调用 `download_all_pages()`；「单P」调用 `download_video_with_audio(..., page=n)` 或 `download_audio(..., page=n)`。
4. 如视频属于合集，仍可通过普通下载流程下载当前视频；需要整个合集时切换到「合集」页签或调用 SDK 的 `download()`/`download_season()`。

#### 收藏夹

1. 输入 media_id 或收藏夹链接。
2. 选择视频或音频、清晰度、线程数和保存目录。
3. worker 先调用 `get_fav_info()` 获取收藏夹名称、`get_fav_bv()` 获取 BV 列表，然后将列表传给 `VideoService.download_fav()`。

#### 合集

1. 输入合集内任意 BV、sid 或合集 URL。
2. 如果输入的是 BV，后端通过 `fetch_season(bvid=...)` 找到所属合集；如果是 sid，则传入 sid 和可选 mid。
3. worker 将合集结构传给 `download_season(season=...)`，按 episode/page 建立总进度。

#### UP主

1. 输入 mid 或空间链接。
2. 后端翻页调用投稿列表接口获取全部 BV，再查询昵称作为目录名。
3. 按视频逐个进入普通分P下载；并发时可勾选多账号分流。

#### 装扮

1. 输入关键词并点击「搜索」。
2. `SearchWorker` 同时调用表情包搜索和装扮商城搜索，结果统一显示为可勾选列表。
3. 勾选项目后点击「下载选中」；装扮素材固定写入 `output/收藏集/`，不使用普通视频保存目录。
4. `threads > 1` 时按选择顺序分配并发任务；若提供多账号，则轮询不同 `BiliSession`。

### 3.5 登录、多账号和设置

- 登录页首次显示时自动启动一次二维码生成；手动点击可重新生成。
- 扫码成功后，后台拿到 `set-cookie`，`AccountManager` 解析 uid、保存 cookie、更新 `accounts.json`、切换当前路径，然后发出 `login_changed` 信号刷新 UI。
- 设置页修改 cookie 目录时，会迁移默认目录下的账号 cookie 并更新映射；自定义路径不会被强行移动。
- 下载管理器对视频/收藏夹/合集/UP主要求有效登录；表情包、收藏集和装扮 CDN 资源允许匿名访问。

### 4.1 最简单的登录+下载视频

如果用户只想立即使用 SDK 下载一个视频，可以直接运行：

```bash
python -m examples.quick_start
```

这个示例会：

1. 调用 `LoginService.qr_login()` 生成二维码并轮询扫码状态；
2. 登录成功后保存 cookie；
3. 创建 `VideoService`，调用 `download_video_with_audio()` 下载视频和音频；
4. 使用 ffmpeg 合成 mp4，并打印最终文件路径。

需要换视频时，修改 `examples/quick_start.py` 中的 `BVID`：

```python
BVID = "BV1ov42117yC"
```

首次运行需要扫码；之后 cookie 会复用当前账号的保存路径。

### 4.2 运行其他示例

除 `quick_start.py` 外，其他示例默认只查询或展示结构，批量下载和真实写操作通常放在函数中并通过注释/手动调用启用，避免用户误下载大量内容或误发评论、私信。

例如查看视频示例：

```bash
python -m examples.video
```

如需执行其中的其他功能，打开对应文件，在自己的参数和账号确认无误后调用相应函数。原始 API 参数、鉴权字段和返回值说明仍保留在各 service 的 docstring 中。

```bash
pip install -r requirements.txt
pytest tests/ -m "not network"
pytest tests/
pyinstaller bilitools.spec --noconfirm
```

需要注意：

- 频繁请求可能触发 -412，SDK 已提供退避、节流和并发风控协调，但不能保证绕过服务端限制。

- 评论、私信、签约等写操作会真实改变账号状态。
- 请遵守 bilibili 用户协议和相关法律法规，仅用于个人学习和合规用途。
